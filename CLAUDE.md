## Project Overview

This is a **Spring Boot 3.2.3** application demonstrating Kafka messaging with Avro serialization and AWS SQS integration using LocalStack. The project runs in a Dockerized environment with Kafka, ZooKeeper, Schema Registry, and LocalStack SQS.

**Technologies:**
- Java 17
- Spring Boot 3.2.3
- Spring Kafka with Avro serialization (Confluent Schema Registry)
- AWS SQS via Spring Cloud AWS 3.1.0
- LocalStack for local AWS services
- Lombok
- Bean Validation (Hibernate Validator)
- JaCoCo for test coverage
- Maven

## Build and Development Commands

### Environment Setup
```bash
# Start all Docker services (Kafka, ZooKeeper, Schema Registry, LocalStack)
docker-compose up -d

# Initialize LocalStack SQS queue and send test message
bash scripts/init-localstack.sh
```

### Maven Commands
```bash
# Clean and build project
./mvnw clean install

# Run tests
./mvnw test

# Run specific test class
./mvnw test -Dtest=ProducerPessoaTest

# Run application
./mvnw spring-boot:run

# Generate Avro classes from schemas
./mvnw generate-sources

# Generate JaCoCo coverage report
./mvnw jacoco:report
# Report available at: target/site/jacoco/index.html
```

### Docker Services
The application depends on Docker services defined in `docker-compose.yml`:
- **Kafka broker**: localhost:19092 (external), kafka-broker-1:9092 (internal)
- **ZooKeeper**: localhost:2181
- **Schema Registry**: localhost:8081
- **LocalStack SQS**: localhost:4566

## Architecture

### Package Structure
```
com.github.kafka/
├── consumer/         # Kafka consumers with @KafkaListener
├── producer/         # Kafka producers
├── converter/        # Converts between Avro models and DTOs
├── dto/              # Data Transfer Objects with Bean Validation
├── exception/        # Custom exceptions and error handlers
│   └── errorhandler/ # Kafka error handling (CustomKafkaErrorHandler)
├── sqs/              # AWS SQS message listeners
└── utils/            # Validation utilities
```

### Message Flow Architecture

**Producer → Kafka → Consumer:**
1. Application sends Avro-serialized messages via `ProducerPessoa`/`ProducerProduto`
2. Messages are published to Kafka topics configured in `application.properties`
3. Consumers listen with manual acknowledgment mode
4. Avro objects are converted to DTOs and validated using Bean Validation
5. Errors are handled by `CustomKafkaErrorHandler` (acknowledges failed messages)

**SQS Integration:**
- `SQSMessageListener` consumes messages from LocalStack SQS queue
- Configured to use LocalStack endpoint (localhost:4566)

### Avro Schema Generation

Avro schemas are defined in `src/main/resources/avro/*.avsc` and compiled to Java classes during the `generate-sources` phase via `avro-maven-plugin`. Generated classes appear in `target/generated-sources/avro/`.

**Important:** After modifying Avro schemas, run `./mvnw generate-sources` to regenerate Java classes.

### Kafka Configuration Details

- **Manual acknowledgment mode**: Consumers use `Acknowledgment.acknowledge()` to commit offsets
- **Error handling**: `CustomKafkaErrorHandler` intercepts exceptions, logs errors, and acknowledges messages to prevent reprocessing
- **Avro serialization**: Uses Confluent's `KafkaAvroSerializer`/`KafkaAvroDeserializer` with Schema Registry
- **Topic configuration**: Topics are configured via properties: `spring.kafka.consumer.topic.pessoa` and `spring.kafka.consumer.topic.produto`

### Validation Pattern

The codebase uses a custom validation pattern:
1. Consumers receive Avro objects from Kafka
2. Converters transform Avro objects to DTOs (which have `@NotNull`, `@NotBlank`, etc. annotations)
3. `ValidationUtils.validate()` performs Bean Validation and throws `ValidationException` on failure
4. Validation exceptions are caught by the error handler

### Application Startup Behavior

The `KafkaApplication` main class includes a `CommandLineRunner` bean that automatically sends test messages for `Pessoa` and `Produto` on application startup. This is for demonstration purposes.

## Testing

Test classes follow the pattern `*Test.java` and are located in `src/test/java/`. The project uses:
- Spring Boot Test
- Spring Kafka Test (embedded Kafka for integration tests)
- Mockito 5.11.0
- Awaitility (for async testing)

Coverage reports are generated by JaCoCo during the `prepare-package` phase.

## LocalStack SQS Commands

```bash
# Create queue
aws --endpoint-url=http://localhost:4566 sqs create-queue --queue-name my-queue-name --region us-east-1

# List queues
aws --endpoint-url=http://localhost:4566 sqs list-queues --region us-east-1

# Send message
aws --endpoint-url=http://localhost:4566 sqs send-message \
  --queue-url "http://sqs.us-east-1.localhost.localstack.cloud:4566/000000000000/my-queue-name" \
  --message-body "Test message" \
  --region us-east-1
```

## Important Configuration Files

- `application.properties`: Kafka consumer/producer settings, Schema Registry URL, SQS configuration
- `docker-compose.yml`: Defines Kafka broker, ZooKeeper, Schema Registry, and LocalStack services
- `pom.xml`: Maven dependencies and plugin configuration (Avro, JaCoCo, Spring Boot)
- `src/main/resources/avro/*.avsc`: Avro schema definitions
